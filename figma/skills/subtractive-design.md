# Subtractive Design

Work within the selected or named scope and the user's request. Review requests produce findings without edits; implement changes when requested. Use available context, disclose inaccessible evidence, and preserve unrelated work.

Use absence to create hierarchy, calm, and focus. Keep an element because it serves the task, not because it was easy to generate.

## Define what must remain

Identify what the selected screen or flow must let people accomplish. Preserve the supplied product intent, brand, and required functionality. Simplification should reduce decisions without hiding necessary capabilities.

## Remove with purpose

1. Identify duplicated information, equal-weight actions, unnecessary chrome, decorative layers, and options unrelated to the current decision.
2. Remove or demote elements that do not help the task.
3. Use existing spacing, typography, and component hierarchy to clarify what remains.
4. Reconsider whether repeated labels, borders, shadows, and motion still earn their place.
5. Stop before removing information, accessibility, or affordances people need.

Prefer one clear primary action when the task has one. Keep secondary actions available and visibly secondary. Use progressive disclosure for necessary complexity; do not hide critical actions behind hover or an unexplained icon.

Useful defaults can remove setup. An ever-growing preferences panel should not substitute for deciding the normal experience. Empty space does not need filling.

## Figma Design

Inspect the selected frame, nearby components, and relevant states. Preserve reusable component relationships and available variables. Apply the smallest scoped change that improves hierarchy; avoid broad library changes for local cleanup.

Recheck long content, empty states, and compact layouts after removing elements. A comparison frame can help when the user requests alternatives; do not multiply variants merely to show activity.

## Make

Remove redundant interface elements and their obsolete local behavior when appropriate, while preserving necessary routes, state, and accessible names. Recheck focus order when controls move or disappear.

Confirm that simplification retains the task on touch, keyboard, and reduced motion. A cleaner screenshot can conceal lost functionality.

## Deliver

Explain what was removed or demoted and why the remaining hierarchy is clearer. Verify the affected path in the available prototype or runtime and distinguish those checks from canvas inspection.

If further removal would make the task harder to discover or complete, stop. Restraint includes knowing what to keep.
